# Установка обновления FunFernus Bank

## 1. Обязательно сделайте резервную копию

Полностью остановите Minecraft-сервер и Discord-бота. Скопируйте в отдельную папку:

- `plugins/FunFernusBank/`
- `plugins/FunFernusBankBridge/`
- текущие JAR-файлы обоих плагинов;
- папку `data/` Discord-бота;
- файл `.env` Discord-бота;
- пользовательские баннеры бота, если они хранятся рядом с проектом.

Не обновляйте плагины через `/reload` или PlugMan. Нужен полный перезапуск сервера.

## 2. Minecraft-плагины

1. Удалите старые JAR-файлы `FunFernusBank` и `FunFernusBankBridge` из папки `plugins`.
2. Положите туда:
   - `FunFernusBank-3.2.0-network.jar`
   - `FunFernusBankBridge-4.4.0-network.jar`
3. Не удаляйте существующие папки данных плагинов.
4. Запустите сервер на Java 21.
5. Убедитесь, что сначала загрузился `FunFernusBank`, затем `FunFernusBankBridge`.

При первом запуске выполняются миграции:

- старые роли `JUDGE/POLICE/GOVERNOR` → `USER` с резервной копией файла аккаунта;
- старые штрафы получают постоянный номер для интерфейса;
- одиночный терминал бизнеса переносится в список терминалов сети;
- создаётся список безвозвратно удалённых бизнесов при первом таком удалении.

## 3. Discord-бот

1. Распакуйте `FunFernusBankBot-4.4.0-network.zip` в новую папку.
2. Перенесите из старой установки только:
   - ваш `.env`;
   - нужные данные из `data/`;
   - папку пользовательских баннеров, если она использовалась.
3. Не заменяйте новые `.py`-файлы старыми.
4. Установите зависимости:

```bash
python -m pip install -r requirements.txt
```

5. Запустите через `start.bat`, `start.sh` или `python bot.py`.
6. В Discord откройте конфиг-панель и проверьте каналы, администраторов и технический канал моста.

Устаревшая роль `fine_issuers` автоматически удаляется из настроек. Выдача штрафов доступна только пользователям из списка администраторов банка и владельцу сервера Discord.

## 4. Новые параметры `config.yml`

```yaml
business:
  low-stock-threshold: 16
  product-name-max-length: 48

business-limits:
  max-businesses-per-player: 3

business-network:
  first-business-terminals: 3
  terminals-per-additional-business: 3

business-notifications:
  low-stock-threshold: 16
```

Если старый `config.yml` уже существует, Bukkit обычно не дописывает новые ключи в пользовательский файл автоматически. Добавьте блоки вручную либо сравните файл с копией из исходников. В коде есть безопасные значения по умолчанию, поэтому отсутствие ключей не должно останавливать запуск.

## 5. Проверка после запуска

Проверьте на тестовом аккаунте:

1. Снятие 1–64 АР через банкомат и заполненный инвентарь.
2. Просмотр штрафа: первый клик только открывает выбор оплаты.
3. Оплату штрафа наличными и со счёта; повторный клик после оплаты.
4. Discord-выдачу штрафа со всеми единицами срока.
5. TAB у `/biz category add`, `/biz product add` и `/bankadmin freeze`.
6. Добавление товара с пользовательским названием и ошибочным названием.
7. Сценарий склада: первоначально мало → без уведомления; выше порога → снова ниже → одно уведомление.
8. Создание 1/2/3 бизнесов и лимиты терминалов 3/6/9.
9. Три попытки разрушения терминала и запрет повторного создания того же бизнеса.
10. Консоль на наличие `NoSuchMethodError`, `IncompatibleClassChangeError` и ошибок чтения старых JSON.

## Важное замечание

Исходный комплект был предоставлен только в виде JAR с декомпилированными исходниками, без исходного Gradle/Maven-проекта и без тестового сервера с реальными данными. Комплект прошёл сборку и автоматические проверки, но перед установкой на основной сервер обязателен короткий запуск на копии сервера и данных.
